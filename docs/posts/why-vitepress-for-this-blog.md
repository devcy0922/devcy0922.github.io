# 블로그를 만들었다

그동안 뭔가를 만들 때 기록을 아예 안 한 건 아니었다.

README에도 남기고, 이슈에도 쓰고, 혼자 보는 메모에도 적었다. 문제는 나중에 다시 찾기가 어려웠다. 프로젝트가 바뀌면 그때 했던 고민도 같이 묻혔다.

그래서 그냥 블로그를 하나 만들었다.

포트폴리오처럼 잘 꾸며놓고 끝내는 사이트보다는, 만들다가 생긴 생각이나 삽질을 계속 적을 수 있는 곳이 필요했다.

## VitePress를 썼다

프레임워크는 VitePress다.

Astro나 Next.js도 잠깐 생각했는데 굳이 바꿀 이유가 없었다. Markdown 파일 하나 추가하면 글이 되고, 정적 빌드라 운영할 것도 거의 없다.

내가 블로그에서 하고 싶은 건 결국 이거였다.

```text
글을 쓴다
커밋한다
끝
```

블로그 자체를 또 하나의 사이드 프로젝트로 만들고 싶지는 않았다.

글 목록도 Markdown frontmatter를 읽어서 자동으로 만들었다.

```js
export default createContentLoader('posts/*.md', {
  transform(raw) {
    return raw
      .filter((page) => page.frontmatter.date)
      .sort((a, b) =>
        +new Date(b.frontmatter.date) - +new Date(a.frontmatter.date)
      )
  }
})
```

새 글을 쓸 때 다른 파일을 같이 수정할 필요는 없다.

## 예전 사이트에서 많이 뺐다

기존 개인 사이트는 보여주고 싶은 게 너무 많았다.

경력, 프로젝트, 아키텍처, 데모, 다국어, 각종 숫자와 상태까지 한 화면에 다 넣었다. 하나씩 보면 필요한 기능인데 같이 놓고 보니 정신이 없었다.

이번에는 많이 지웠다.

다국어 기능도 빼고, 특정 프로젝트 데모를 전면에 두는 것도 그만뒀다. 프로젝트 카드도 줄였다.

지금은 대충 이 정도면 충분하다고 생각한다.

```text
Home
Posts
Projects
About
```

검색, RSS, sitemap 정도는 정적 빌드에서 같이 만든다.

## 뭘 쓸지는 아직 정하지 않았다

AI 플랫폼 이야기만 쓰지는 않을 생각이다.

LLM Gateway를 만들다가 잘못 넣었던 기능도 쓸 수 있고, 서버 옮기다가 삽질한 것도 쓸 수 있고, 사이드 프로젝트를 만들었다가 접은 이유도 쓸 수 있다.

잘 정리된 정답을 쓰기보다는 그때 내가 왜 그렇게 판단했는지를 남기고 싶다.

몇 달 뒤에 다시 봤을 때 "그때 왜 저렇게 했지?"를 확인할 수 있으면 충분하다.

일단 만들었으니 이제 글을 쓰면 된다.
